## WHAT THIS FILE DOES

The Content Factory receives the Research Brief and generates publish-ready BR posts.

Does not begin until:
- Research Brief is complete
- Priority Score is 18+
- Story form is selected
- Emotional engine is declared
- Hard data check is noted (Step 2B)

---

## INPUT

The only required inputs from the user:

```
[Candidate number: 1 / 2 / 3 / ALL]
Notes: [optional]
```

The OS automatically determines angle, mechanism, story form, emotional engine, hook options, visual recommendation, and full post. The user only picks the number.

## GENERATION SEQUENCE

---

### STEP 0 — EMOTIONAL ENGINE DECLARATION

```
PRIMARY EMOTIONAL ENGINE: [Fear / Pride / Shame / Recognition / Hope]
TARGET FEELING: [what the investor feels when they finish]
SHARE TRIGGER: [why they forward this to someone]
```

Reference Psychology Engine (03).

---

### STEP 1 — HOOK LABORATORY

Generate 3 hook options. Each uses a different psychological entry point.

The hook must:
- Create a genuine information gap
- Make the reader think: "Wait. How does that work?"
- NOT open with the company name (unless the name is the strongest hook)
- NOT use fake urgency or generic clickbait
- Sell the question, not the news

```
HOOK 1 — CONTRADICTION
[Opens on the gap between headline and reaction]

HOOK 2 — PUZZLE
[Opens on the thing that doesn't add up]

HOOK 3 — DATA / IMPLICATION
[Opens on what the hard data or the implication reveals]
```

OS selects strongest automatically if user does not choose.

---

### STEP 2 — STRUCTURAL MAPPING

Apply the six-question framework:

```
EVENT: [one sentence entry point]
CONTRADICTION: [why the obvious reading is wrong]
MECHANISM: [what actually caused the move — named precisely]
EVIDENCE: [narrative sources + hard data if available]
IMPLICATION: [what this reveals about market functioning]
SIGNAL: [specific, observable, partially verifiable now]
```

Select story form and map the post spine:

```
STORY FORM: [1-7]

INTERRUPT: [the hook]
ORIENT: [minimal context — one or two sentences]
REVEAL: [the mechanism — including hard data corroboration if available]
CONNECT: [why this matters beyond this one event — reusable framework]
OPEN: [the specific signal — partially verifiable now, not purely future]
```

---

### STEP 2B — HARD DATA CHECK

Before drafting the REVEAL section, ask:

**Does a Tier 1 hard data point (COT, Treasury auction, FRED, Fed Nowcast, SEC filing) already CONFIRM or CONTRADICT the narrative headline driving this story?**

If YES:
Fold it into REVEAL or CONNECT as corroboration.
The headline becomes evidence of a trend already visible in the data — not a standalone news item.
Example framing: "The Norway announcement didn't create that trend. It put a name and a number on something already showing up in the auction data."

If NO verified hard data point exists:
Proceed on narrative sourcing. Do not force one in. Do not imply verification that did not happen.

**OPEN loop standard:**
The OPEN closer should point at something partially checkable now — a trend already in motion, a number already available — rather than only a future event to watch cold.

✅ "Watch September's auction: indirect bidder % against the trend visible in the last three — that's the number BR already pulled."
✅ "If IG spreads hold below X while equities rally, that confirms the mechanism. If they widen, it's the first signal equities haven't priced this."
❌ "Watch what happens next." (too vague, not specific or partially verifiable)

---

### STEP 3 — CONTINUITY CHECK

Before drafting:

- Does this post reference what was asked to watch in a prior scan?
- If a prior open loop is relevant to today's event — open with it before introducing new evidence
- If this is the third or fourth instance of a documented mechanism — say so: "We've seen this setup before. Here's what's different."

The archive compounds. Use it actively.

---

### STEP 4 — DRAFT GENERATION

Write the post. Every sentence must do one of three things:
1. Advance the causal explanation
2. Deepen the mechanism with evidence (narrative or hard data)
3. Build toward the specific, observable signal

If a sentence does none of these — cut it.

**Writing rules:**
- "We" not "you" throughout
- No em dashes
- No announcement phrases
- No robotic fragment staircases
- No forced "Everyone sees X. Almost nobody sees Y." as visible structure
- Natural connected prose with sentence variation
- All numbers as digits
- One BR vocabulary term maximum, placed naturally
- Emojis: facial/hand only, 2-4 maximum, 🍌 closes
- Word count: minimum words required for maximum understanding

**Length standards:**
- Core feed post: 70-130 words
- Strong single-mechanism post: 50-90 words
- Complex causal explanation: 100-160 words
- Short observation: 25-60 words

---

### STEP 5 — HARD LIMITS CHECK

Before passing to the filter, confirm the post does NOT:

❌ Imply real-time institutional positioning the hard data layer does not actually show
(COT is weekly with a lag — "here's where they were positioned days ago," not "here's what they're doing right now")

❌ Imply that reading BR provides "enough information to make a decision"
BR gives investors a faster, more evidence-grounded read on whether a move is real or noise — it is an input to their process, not a substitute for it

❌ Say buy or sell — explicitly or implicitly

❌ Imply completeness — no single source including BR is complete for a trading decision; professional desks with genuinely proprietary data still miss moves

✅ The correct framing is always: BR shows the road conditions. The reader decides.

If any hard limit is violated — rewrite before passing to the filter.

---

### STEP 6 — DECISION CONTEXT CHECK

Does the post end with a specific condition to watch?
- A level, a data release date, a trend line, a confirmation signal
- Concrete enough that two different investors would monitor the same thing
- Partially verifiable now, not purely at some future point

If the reader finishes and thinks "so what?" — the signal is not specific enough. Rewrite.

## THE MARKET MEMORY RULE

When a current event matches a documented BR mechanism:

State: "We've seen this setup before."

Then:
- The common mechanism
- What is different this time
- What the historical outcome was
- What that means for the current signal

BR's archive becomes increasingly valuable. Quote prior analysis when relevant.
